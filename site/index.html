GitHub Benchmarks Report a difference

The same mdast as remark-parse, much faster.

samemark parses markdown into the same tree as mdast-util-from-markdown with GFM, positions included, and falls back to that parser for anything it does not reproduce exactly. Below, both run live in your browser: no server, no tracking, nothing is sent anywhere.

Streaming demo: a chat answer, token by token

One long answer is streamed into two panes, 40 characters per update. On the left, react-markdown re-parses and re-renders the whole message on every update, which is what most chat UIs do. On the right, samemark/stream parses only the new text and React skips every finished block (examples/react-chat).

Both sparklines share one scale: 0 to 1 ms per update, left edge is the first update. Each number is the time of one synchronous React update (parse, render and DOM commit; layout and paint are not included), measured with performance.now() in your browser, on this device. Both panes run on the same thread, one after the other, in alternating order. No throttling is applied: open this page on a phone to see the difference on a slower device. The checked claim is the badge: the two panes must hold identical HTML, compared every 10 updates and at the end. Controlled measurements (Chromium, 4x and 6x CPU throttling, 7 rounds) are in the README.

Playground: the same tree?

Type markdown. Both parsers run in your browser on every change and the two trees are compared node by node, positions included. The sample is deliberately awkward: nested emphasis, a footnote, a table with escaped pipes, a reference definition used before it appears, raw HTML, autolink literals.
